# 画面フロー・フェーズ設計

## フェーズ遷移図

```
[input] → [config] → [fixedSeat] → [roulette] → [chart] → [finished]
                                        ↑
                                      (戻る)
```

ヘッダーのアイコンボタンからは任意のフェーズに直接ジャンプ可能（フェーズ順を強制しない）。
ただし、前フェーズのデータが揃っていないと後フェーズは正常動作しない。

## 各フェーズの詳細

---

### input（生徒情報の取り込み）

**担当コンポーネント**: `StudentInput`  
**完了条件**: 生徒データが 1 人以上読み込まれること  
**次フェーズへの遷移**: `App.tsx` の `handleStudentsLoaded` が呼ばれた時  

**処理内容**:
- CSV ファイルのアップロードまたはテキスト貼り付けで生徒データを読み込む
- 生徒IDは CSV に含まれていなければ自動生成（UUID）
- デフォルトの座席マップ（6 行 × 7 列）を生成して Context にセット（既存マップがある場合はスキップ）

---

### config（座席レイアウト設定）

**担当コンポーネント**: `SeatConfig` → `SeatMapConfig`  
**完了条件**: 行数・列数が確定し、使用不可席の設定が完了  
**次フェーズへの遷移**: `SeatMapConfig` 内の確定ボタン → `onConfigFinished` コールバック経由  

**処理内容**:
- 行数・列数の変更（デフォルト: 6 行 × 7 列、最大: 100 席）
- 各座席の使用可否（`isUsable`）の切り替え（障害物のある席などを除外するため）
- 更新された `SeatMapData[]` を Context にセット

---

### fixedSeat（座席指定 / 許可エリア設定）

**担当コンポーネント**: `FixedSeatConfig`  
**完了条件**: 任意（設定なしでも次へ進める）  
**次フェーズへの遷移**: 「座席指定を確定し次へ」ボタン押下  

**処理内容**:
- 生徒選択エリアと座席マップを表示
- 生徒を 1 人選んでから、その生徒が座れる座席（許可エリア）を複数選択する
  - **個別選択**: 座席をクリックして 1 席ずつトグル
  - **範囲選択**: 始点 → 終点の 2 回クリックで矩形範囲内の使用可能席をまとめて追加
  - 1 席だけならピンポイント固定、複数選べばその中から抽選
  - 同じ席を複数生徒の許可エリアに含められる（重複可。生徒ごとに色分け表示）
- 「条件が多すぎて希望が埋まっている場合は無視してランダム割り当てする」旨の注意を常設表示
- 登録された `FixedSeatAssignment[]` を Context にセット
- この時点では `Student.isAssigned` は更新しない（実際の割り当てはルーレットフェーズで行う）

---

### roulette（ルーレット）

**担当コンポーネント**: `RouletteDisplay`  
**完了条件**: 全生徒の座席割り当てが完了（`unassignedStudents.length === 0`）  
**次フェーズへの遷移**: 「座席表へ」ボタン押下（全員割り当て完了後に活性化）  

**処理内容**:
- 未割り当て生徒を 1 人選択し、`requestAnimationFrame` ベースのアニメーションで空席をランダム点灯
- 「ストップ」で点灯中の座席に確定。確定後に `students` と `seatMap` の両方を更新
- ルーレット実行中に座席をクリックすると、その座席を手動選択できる
- 許可エリア指定のある生徒は、`highlightScope` に応じて点灯範囲が変わる（演出のみ。当選席は常に許可エリア内）
  - `'all'`: 全空席を点灯（ピンポイント固定でも普通の抽選に見せる）
  - `'area'`: 許可エリア内のみ点灯（希望を尊重していると示す）
- 「全員一括割り当て」で残り全員をランダム割り当て（許可エリア指定のある生徒を「選べる空席が少ない順」に先に処理）
- 「リセット」で全割り当てをクリア（座席指定の設定は維持）

**ルーレット停止時の座席決定の優先順位**:
1. ルーレット実行中にユーザーがクリックした座席 → そのクリック座席に決定（教師の手動上書きを最優先）
2. 点灯していた座席が許可エリア内ならその座席（全体点灯で許可エリア外に止まった場合は不採用）
3. 許可エリア内のランダムな空席。許可エリアがすべて埋まっていれば全空席からランダム（条件を無視・エラーは出さない）

**関係性制約チェック**:
- `relationConfig` が設定されていれば隣接座席（上下左右 4 方向）をチェック
- `co_seat`: パートナーが隣接していなければ無効
- `no_co_seat`: パートナーが隣接していれば無効
- 現在 UI から `relationConfig` を設定する手段がない（`RelationConfig` コンポーネントが無効化中）

---

### chart（座席表確認・調整）

**担当コンポーネント**: `SeatingChart`  
**完了条件**: 「座席調整を完了する」ボタン押下  
**次フェーズへの遷移**: ボタン押下で `finished` へ  

**処理内容**:
- 割り当て結果をビジュアルな座席グリッドで確認
- ドラッグ&ドロップで生徒の座席を入れ替え（生徒同士のスワップ）
- 未割り当て生徒がいる場合は自動的に `roulette` フェーズに戻す

---

### finished（出力）

**担当コンポーネント**: `SeatingChart`（読み取り専用）+ `OutputPanel` + `PrintableSeatChart`  
**完了条件**: ユーザーが出力操作を行う  

**処理内容**:
- 表示項目（出席番号・氏名・ふりがな・情報1〜3）をチェックボックスで選択
- PDF 出力: `html2canvas` で `id="main-seating-chart-container"` の要素をキャプチャ → jsPDF で A4 横向き PDF 生成
- クリップボードコピー: タブ区切りテキスト形式（表計算ソフトへの貼り付け用）

## データの保存・読み込み

ヘッダー右上の「⋮」メニューからいつでも操作できる。

| 操作 | 内容 |
|------|------|
| データ保存 | 全 Context 状態をローカルストレージに保存（現在のフェーズも含む） |
| データ読み込み | ローカルストレージから状態を復元（現在のデータは上書きされる） |
| データリセット | ローカルストレージを削除し、全状態を初期化（input フェーズに戻る） |
